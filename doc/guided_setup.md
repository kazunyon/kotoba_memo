# 紙芝居形式の初回設定（PC版0.4.0）

初回起動で「初回設定ガイド」が開きます。12枚のカードを順番に進めます。各カードは、その作業の図、押すボタン、コピーする文字、完了確認をまとめています。Google画面の図は説明用の再現図で、実際の画面キャプチャではありません。

## 利用者の操作

- 「最初から準備する」で開始し、自分のGoogle CloudプロジェクトIDを貼り付けます。
- 「Googleの設定ページを開く」「Cloud Shellを開く」で、選んだプロジェクトの該当ページを開きます。
- 長い命令を手入力せず「命令をコピー」で貼り付けます。内容は必要な場合だけ展開して確認できます。
- 本人がGoogle画面で行う同意・請求先等は確認して「次へ」を押します。Cloudの準備・認証情報保存・最終設置には手動の完了チェックを使いません。
- 「ここで休む」で進み具合を保存し、次回「続きから再開する」を押します。
- 設置済みなら「設置済みのURLがある」で直接接続できます。
- 設置後も、アプリの「ヘルプ → 初回設定ガイドを開く」でガイドへ戻れます。編集中のメモは先に保存してください。

最後の接続確認では実際の`/api/config`を読み、設置先originとGoogleクライアント設定を確認します。その後のログイン・アカウント確認・保存・スマホでの表示は、本人の端末で確認します。ガイドの確認チェックだけで実機同期の成功とは判定しません。

## できるだけ自動にした部分

Cloud Shellで次の3種類の命令を実行します。プロジェクトIDを入れた命令はガイドが作ります。

1. `setup.sh prepare`：必要なAPI、アプリ用アカウント、専用ビルドアカウントと`roles/run.builder`、準備サービスを設定。混雑や権限反映待ちは回数を制限して再試行します。
2. `setup.sh credentials`：クライアントIDと秘密の値を、入力待ちに合わせて貼り付けます。Secret Managerの作成とバージョン確認、32バイトの暗号化キー生成をまとめ、最終設置へ自動で進みます。
3. `setup.sh finish`（通常は自動、失敗後の再開にも利用）：3つの有効な秘密情報を確認し、アプリ用アカウントへその3つだけの参照権限を付け、設定済みのCloud Runを設置します。

課金登録、Google認証のブランディング・対象ユーザー・権限・クライアント作成は、本人がGoogleの画面で行います。Cloud Shellの初回認証も本人の操作です。費用は本人のプロジェクトへ発生します。

## 秘密の値の扱い

秘密の値はガイドへ入力しません。まず命令を実行し、クライアントIDの入力待ちにIDを貼り付けます。次の入力待ちで、Googleからコピーした秘密の値を貼り付けます。文字は画面へ表示されません。命令履歴に秘密の値を入れません。

秘密の値をコピーした後に「命令をコピー」を押すと、コピー内容が置き換わるため、順番を図解しています。新しい秘密の値の表示画面は保存が終わるまで閉じません。秘密の値をスクリーンショット、チャット、紙へ記録する必要はありません。

保存済みの有効な秘密情報は再入力せず、既存のセッション暗号化キーも保持します。変更したOAuthクライアントへ移行する操作や、鍵のローテーションはこの初回設定とは別に管理します。秘密の値を紛失した場合はGoogleのクライアント画面で再発行が必要です。追加上限や利用中の秘密情報の扱いは管理者へ確認してください。

## 印刷用マニュアル

「図解マニュアル・印刷」を押すと、ガイドと同じ図解の14ページを表示します。印刷画面でA4またはPDF保存を選びます。入力済みのプロジェクトIDと設置先URLを差し込めます。秘密の値は含みません。

ソースでは `desktop/setup-manual.html` を開けます。説明文・URL・コピー内容は`desktop/setup-guide.js`、図は`desktop/setup-diagram.js`を共通利用しています。

## エラーの案内

「うまくいかないとき」へエラー結果を貼り付けると、混雑・操作権限・秘密情報の保存漏れ・請求先に分け、該当手順へ戻るボタンを表示します。エラー結果は保存しません。判別できないエラーでは原因を断定せず、管理者への相談を案内します。

## 設定結果の自動受け取り

Cloudの準備と最終設置の成功後に `kotoba-プロジェクトID-prepare.kotoba-setup` または `kotoba-プロジェクトID-finish.kotoba-setup` を作り、Cloud Shellのダウンロードを呼び出します。ファイルの内容はバージョン、プロジェクトID、段階、canonical Cloud Run URLのみで、認証情報は含みません。

Windowsではこの拡張子をことばメモに関連付けます。ダウンロードしたファイルを開くとアプリが受け取ります。関連付けを利用できない場合は、PCガイドの「設定結果を受け取る」でそのファイルを選びます。Cloud Shellの自動ダウンロードが使えない場合は、表示されたファイルをCloud Shellのファイル一覧から取得します。URLを探したり選んだりする必要はありません。

アプリはファイルサイズ・形式・HTTPS Cloud Run URL・選択済みプロジェクト・準備済みURLの一致を検査します。準備結果から設置先とリダイレクトURIを自動生成し、Google同意設定へ進みます。最終結果では実際の `/api/config` を読み、設定済みフラグ・origin・WebクライアントIDを確認してログイン画面へ進みます。接続に失敗した場合は完了扱いにせず、結果を再選択できます。

結果ファイル自体は署名付きGoogle証明ではありません。準備結果はCloudスクリプトの成功報告であり、非公開の準備サービスへPCからアクセスできたとは表示しません。最終結果は実際の接続確認を加えますが、OAuthの同意や本人のDrive保存はログイン後の実機確認が必要です。PCにはGoogle Cloudの管理用資格情報を持たせません。Googleの本人確認・プロジェクト選択・請求先・同意画面・OAuthクライアント作成はGoogle画面で行います。

休止・再開では秘密情報を含まないURL・プロジェクト・受領段階を保存します。古い手動チェックは自動確認の完了として扱いません。結果受領後のログインは接続先の再確認を行います。

## 検証の範囲

結果解析、別プロジェクト・別URLの拒否、接続先の設定確認、古いチェックの無効化、梱包ファイルの欠落防止をテストします。Cloudスクリプトは模擬gcloudを使い、準備結果の生成、認証保存から最終設置への自動進行、既存暗号化キーの保持を検証します。

ブラウザでの確認はElectronのファイル選択と接続を模擬します。実際のGoogle Cloud設置、Cloud Shellダウンロード、Windowsでの拡張子関連付けと起動はこの環境からは未確認です。

新しいsetup.exeはGitHubへ変更を反映し、「Build Windows setup.exe」で生成してから配布します。ガイドの準備命令はmainから取得するため、これらの変更をmainへ反映してから利用してください。
